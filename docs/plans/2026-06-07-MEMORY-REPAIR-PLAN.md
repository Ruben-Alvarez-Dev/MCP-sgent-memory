## Phase 1 — Resurrect capture (P0, ~half day)

The cheapest real producer first; the universal proxy stays out of scope.

1. **Claude/Cowork memory bridge**: a launchd WatchPaths (or Hazel rule) on
   the Cowork auto-memory directory copies each new/changed memory .md into
   inbox/. The backpack ingests inbox files into conversations.db + entity
   timeline (the ingest path already exists; it just has no producers).
2. **CLI hook**: CLI-agent-memory and Claude Code hooks append session
   summaries to inbox/ on session end (one JSON/MD file per session).
3. Acceptance: a working session today produces >=1 inbox file ingested,
   visible via entity_timeline_query within 5 minutes.

## Phase 2 — Detection & annotation, Claude-memory inspired (P1, ~1 day)

Borrow what works from Claude's memory design:

1. **One fact, one note, typed frontmatter**: ingested memories normalize to
   name (kebab slug), description (one line, used for recall relevance),
   type: user|feedback|project|reference. Feedback notes REQUIRE Why +
   How-to-apply fields. Store in vault, index in SQLite.
2. **Index per kind** (the MEMORY.md pattern): vault/Entidades/INDEX.md
   regenerated by vault_entity_bridge — one line per entity, no content.
3. **Dedup-before-save**: before creating an entity or memory, query FTS5 +
   embedding similarity (BGE-M3 already running on :8081); above threshold →
   UPDATE existing instead of INSERT. Kills the duplicate problem at the root.
4. **Entity linker replaces PROJECT_PATTERNS**: candidates from regex are
   only LINKED if they match the ADR-001 catalog (name or alias, FTS).
   Non-matching candidates go to a quarantine table (status=candidate) with
   NO entity creation. Weekly review promotes or discards.
5. **Wikilink annotation**: vault renders cross-references as [[entity-name]]
   so Obsidian graph reflects relations (relations table already exists).
