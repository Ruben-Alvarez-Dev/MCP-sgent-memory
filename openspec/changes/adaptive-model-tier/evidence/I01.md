## What was verified

Each of the 10 items in `tasks.md` was checked against two independent sources:

1. **Source-code reading** — direct citation of `path:line` for the implementing code, read via the `Read`/`Grep` tools on the working tree at HEAD.
2. **Test execution** — `pytest` run against `tests/core/test_model_tier.py` (and the related `tests/core/test_llm_ollama.py`), verbatim output captured below.

## Result: 8 of 10 tasks ticked, 2 left open

Ticked (cited in `tasks.md`, not repeated here): 1 (HardwareProfile + probes), 2 (backend reachability), 3 (TierResolver.resolve thresholds + role map + overrides), 4 (TTL cache + force_refresh + reactive hook), 5 (atomic persistence + diff + L0 event), 7 (MCP tool + sidecar endpoint), 9 (unit tests), 10 (spec delta).

**Left open — task 6 (wiring, PARTIAL)**: 3 of 4 wiring points are real (startup `_ensure_initialized` at `src/unified/server/main.py:137-143`, heartbeat piggyback at `src/L0_capture/server/main.py:112-118`, `health_check` fresh re-probe at `src/unified/server/main.py:188-197`). The 4th — "LLM/embedding factories (consume map)" — is NOT done: `shared/llm/config.py` only consumes `model_tier.preferred_llm_backend()` (a backend-name string, `ollama`/`llama_cpp`), never `role_models.primary`/`.small` to pick an actual model tag; `shared/embedding.py` does not import `shared.model_tier` at all (`grep -n "model_tier" src/shared/embedding.py` → 0 hits) and sources its model purely from the `EMBEDDING_MODEL` env var. The resolved `role_models` map (embedding/reranker/small/primary/coordinator model tags) is computed, logged, and persisted, but nothing outside `model_tier.py` reads it to select a model.

**Left open — task 8 (instrumentation, NOT wired)**: `TierResolver.record_outcome()` exists (`src/shared/model_tier.py:636-645`) and correctly appends to `data/system/routing-outcomes.jsonl` when called (verified by `tests/core/test_model_tier.py::TestPersistence::test_record_outcome_appends_jsonl`, green). But `grep -rn "record_outcome" src --include="*.py"` shows it is called only from the module-level wrapper (`model_tier.py:705-706`) and from the test file — **zero production call sites** in `L0_capture`, `L0_to_L4_consolidation`, `L5_routing`, or `Lx_reasoning`. Confirmed independently: `data/system/` on disk contains only `hardware-profile.json`, no `routing-outcomes.jsonl` — the method has never fired outside tests. The proposal's "instrumentation ... from day one" acceptance criterion is unmet.
