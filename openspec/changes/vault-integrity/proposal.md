# Change: vault-integrity

- **Status**: proposed (awaiting Rubén's approval) — planning only, no implementation yet
- **Owner**: database · **Release**: v2.2.0 (Phase 2 P0 bugfix batch)

## Why

`bin/vault_processor.py:38` — `is_serialized()` uses `re.match(r"^Ld+_[A-Z]+_d{8}Td{6}_d{5}_(ES|EN).md$", filename)`. Every `d` that should be `\d` is a literal letter "d" instead of a digit class, so the pattern can never match a real generated filename (e.g. `L3_DECISION_20260712T120000_00001_ES.md` has no literal "d" where the pattern expects one). `process_unserialized()` therefore treats every already-serialized file as unserialized forever: infinite re-renames, an ever-inflating `counter.json`, and a fresh duplicate "EN copy" on every watcher tick (P0-10).

Reading the surrounding code surfaced three P1s in the same blast radius (confirmed by direct source read, not assumption):

1. **Three competing `VAULT_PATH` defaults, actively divergent, not just theoretical**: `shared/env_loader.py:126` defaults to `data/vault` and is called by every server entrypoint's `load_env()` *before* `shared/config.py` is read, so its default wins in the real running MCP server; `shared/config.py:94`'s own fallback (`data/Lx-persistent`) is effectively dead code in that path; `shared/vault_manager/__init__.py:44-46`'s module-level fallback is `<repo>/src/vault` (data inside the source tree); `bin/vault_processor.py:6` hardcodes `data/Lx-persistent` and ignores `VAULT_PATH` entirely. `config/mcp.json` does not set `VAULT_PATH`, so today the MCP server and the standalone watcher script write to two **different physical directories** for what is meant to be one vault. All three directories exist on disk right now (verified: `data/vault`, `data/Lx-persistent`, `src/vault`), though only `data/Lx-persistent/README.md` currently has real content — no user notes have been lost yet, but the split-brain is live, not hypothetical.
2. **Two competing counter implementations, neither locked**: `bin/vault_processor.py:40-49` (`get_next_seq`) and `shared/vault_manager/__init__.py:653-665` (`VaultManager._next_id`) each do their own unsynchronized read-`json.loads`-increment-`write_text` on `.system/counter.json`. Concurrent writers (the watcher script + an MCP tool call landing at the same time) can read the same `current` value and hand out duplicate sequence numbers, or interleave a torn write. Notably, `VaultManager` already implements a correct, tested, PID-liveness-aware `O_EXCL` lock (`_acquire_lock`/`_release_lock`, `__init__.py:744-805`) used for note writes — it is simply never applied to the counter.
3. **"EN copy" is `shutil.copy2`, not a translation**: `bin/vault_processor.py:92` (`process_unserialized`) and `:110/:114` (`sync_edited`) byte-copy the Spanish file into the English-named folder. The English folder then contains Spanish prose under an English label — actively misleading, not merely "not yet translated." The copy is also non-transactional: `shutil.move` (ES) then a separate `shutil.copy2` (EN) with no rollback if the second step fails, and the counter is advanced regardless of whether both halves land.

## What

1. **Regex + filename format fix.** Correct the regex (`\d` not `d`) and drop the ad-hoc `_{timestamp}_{ES|EN}` suffix scheme in favor of the format `VaultManager` already produces and tests (`L{layer}_{TYPE}_{seq:05d}.md`, `vault_manager/__init__.py:667-679`, covered by `tests/core/test_vault_manager.py::test_filename_generation`). One filename grammar, one place that defines it, no drift between the two writers.
2. **Single canonical `VAULT_PATH`.** One default (`data/Lx-persistent` — matches the `Lx_persistent_path` config field name and is what `bin/vault_processor.py` already hardcodes), resolved from one place, consumed identically by `config.py`, `env_loader.py`, `vault_manager/__init__.py`'s module fallback, and `bin/vault_processor.py`. Install scripts (`install/app-install.sh`, `install/config.sh`, `scripts/generate-mcp-config.sh`) aligned to the same default for fresh installs. An explicit, reversible, dry-run-capable one-shot consolidation script handles any pre-existing content under the non-canonical paths (currently empty — verified by `find … -name '*.md'` — so this is a safety net for future runs, not an urgent data-rescue).
3. **One locked, atomic counter.** Extract the existing `_acquire_lock`/`_release_lock` pattern out of `VaultManager` into a shared helper; wrap the counter's read-modify-write with it; write `counter.json` via `tempfile.mkstemp` + `os.replace` (not `Path.write_text` in place) so a crash mid-write can't truncate it. Both `VaultManager._next_id` and `bin/vault_processor.py` call the one implementation — no more duplicated logic (DRY, ADR-0007).
4. **ES/EN semantics: explicit mirror, not translation (decision justified in `design.md`).** Real translation needs an LLM call (`ollama-backend` now exists) with its own cost/latency/failure-mode design — out of scope for a P0 bugfix and called out as a non-goal below. Instead: rename the operation and its logs from "EN copy"/"translation" to "EN mirror" everywhere it appears, and make the ES write + EN mirror write **transactional as a pair** (both via tempfile+`os.replace`; if the mirror write fails, the ES move is rolled back and the counter is not advanced; failure is logged at WARNING, never silently swallowed, per `AGENTS.md` §1).

## Impact

- Touches: `bin/vault_processor.py`, `src/shared/vault_manager/__init__.py`, `src/shared/vault_constants.py` (extended with the canonical path resolver), `src/shared/env_loader.py`, `src/shared/config.py`, `install/app-install.sh`, `install/config.sh`, `scripts/generate-mcp-config.sh`.
- New: a small shared lock/counter module under `src/shared/` (extracted from `VaultManager`, not duplicated); a one-shot, idempotent path-consolidation script.
- **Non-goals**: real ES→EN LLM translation (future change, depends on `ollama-backend`/`model-stack-2026`); full hexagonal relocation of `vault_manager`/`vault_processor` into `domain/ports/adapters` — ADR-0007 itself sequences that migration to start at Phase 3 (`hexagonal-shared-split`), so this Phase 2 bugfix stays in `shared/` and does not trigger the boy-scout relocation rule early.
- **Spec baseline note**: `openspec/specs/vault/` does not exist yet (Phase 1 governance scaffolding baseline has not landed). The spec delta in this change (`specs/vault/spec.md`) is written as a **self-contained target end-state**, not an ADDED/MODIFIED delta against an existing baseline. It must be reconciled against the Phase 1 `openspec/specs/vault/` baseline once that lands — this does not block this change.

## Acceptance

- Dropping a Spanish note into `data/Lx-persistent/Inbox` is serialized exactly once; a regression test proves the corrected regex matches the real generated filename on the first pass (the old pattern is kept in a test as a documented "never matches" case).
- A concurrency test (multiple threads/processes hammering the counter for the same layer) yields unique sequence numbers with no duplicates and no `counter.json` corruption.
- `VAULT_PATH` resolves to the same absolute path regardless of entrypoint (MCP server via `env_loader`, standalone `vault_processor.py`, bare `VaultManager` import with no env set) — verified by a test that imports all three resolution paths against a common fixture.
- A simulated failure mid-EN-mirror-write leaves zero partial files on disk and does not advance the counter — verified by a fault-injection test.
