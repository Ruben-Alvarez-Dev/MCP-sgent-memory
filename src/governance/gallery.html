🏗️ 4. L3 — Semantic Memory: Decisions

Architectural decisions with full context: problem, solution, trade-offs, tags. Immutable and versioned.
Timeline Backbone v1.6.1 — Architecture
Problem: 3600+ raw events pile up without structure. MemoryType.ENTITY/RELATION defined in enum but have zero logic. No entity graph, no lifecycle, no temporal ordering. Solution: Per-entity timelines as "guide rope" threading through everything. EntityRegistry + EntityTimeline + RelationManager + Vault bridge. Trade-off: SQLite with FTS5 was chosen over Qdrant-only for simplicity. Qdrant added for semantic cross-entity search.
architecturetimelinev1.6.1
Deep Research Synthesis: Self-Learning & Compliance
Finding: Industry converging on Skills + MCP dual-stack. Skills = procedural memory (SKILL.md), MCP = sensory interface (external tools). Self-learning via Reflexion pattern: feedback→reflection→memory→improved decisions. Compliance via outcome-based verification (tests pass, not "agent said yes").Gap: RalphLoop spec'd in CLI-agent-memory but not implemented in opencode. LACP plugins exist but disabled.
researchmcpskills

📖 5. L4 — Consolidated Narratives

Long-term synthesis from dream cycles — the agent's evolving understanding of its own work

Agent Narrative — Last 24h

The agent began by assessing the migration of Jart-OS from the Mac Mini to the MacBook Pro, identifying broken symlinks, hardcoded VPS paths, and Python version mismatches. After resolving Tier-0 infrastructure, the user requested deep research on self-learning and compliance feedback for CLI agents. The agent conducted research via SearXNG, Perplexica, and internal codebase scan, discovering the Skills + MCP dual-stack standard, the Agent Learning Flywheel, and the RalphLoop state machine pattern.

Following research, the agent implemented the Timeline Backbone v1.6.1: EntityRegistry, EntityTimeline, and RelationManager — transforming 8,206 raw events into 19 structured entity timelines with 20 bidirectional relations. The entity-server was registered as an MCP server in opencode.json.

Finally, the agent built the Memory Governance App following the MCP Apps standard (SEP-1865), with dual transport (HTTP + ui://), interactive dashboard, health scoring, 4-stage notification system, and comprehensive entity lifecycle management.
